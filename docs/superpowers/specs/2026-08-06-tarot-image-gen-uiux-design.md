# 塔罗与图片生成工具 UI/UX 优化设计

> 日期：2026-08-06  
> 状态：已确认  
> 设计方向：B「同系统、双人格」  
> 优化深度：完整体验优化  
> 生图历史：仅保留本次页面会话最近 5 次，刷新后清空

## 1. 背景与目标

本设计覆盖两个公开工具页：

- `/tools/tarot`：塔罗占卜、牌义速查、历史/统计、分享与 AI 深度解读。
- `/tools/image-gen`：提示词输入、尺寸/张数配置、AI 文生图、结果查看与下载。

两个页面已经具备核心功能，但任务性质不同：塔罗是有阶段、有期待感的仪式型体验；图片生成是强调输入效率、结果比较和下载闭环的生产型工具。优化不应强行套用同一种页面网格，而应共享设计系统、状态语言和质量标准，同时保留各自的人格。

### 1.1 目标

1. 塔罗形成稳定、单向、可感知的「问牌 → 洗切 → 抽牌 → 翻牌 → 解读」仪式流程。
2. 图片生成形成「输入 → 参数 → 生成/取消 → 比较 → 查看/下载 → 会话历史」完整闭环。
3. 两页统一使用项目现有 PageShell、PageActHeader、GlassCard、Button、状态色和动效令牌。
4. 修复审计发现的流程竞态、键盘误触、空结果无反馈、灯箱无障碍和下载错误不可见等问题。
5. 满足 320px 至 1536px 响应式、WCAG 2.2 AA、reduced-motion 和项目性能预算。
6. 延续「只有后台管理需要登录」的产品原则：塔罗与图片生成的公开操作不要求登录，但生图接口必须有 IP 限流和明确额度反馈。

### 1.2 非目标

- 不新增第二套主题皮肤或独立于项目 token 的塔罗/生图配色系统。
- 不建设长期图片图库、云端作品库、账号配额中心或跨设备历史。
- 不重写塔罗牌义、洗牌算法或 LLM/生图模型业务逻辑。
- 不引入 GSAP、WebGL、Three.js、平滑滚动库或新的全局状态库。
- 不增加新的持续循环装饰动画。
- 不借机重构无关页面。

## 2. 设计原则

### 2.1 同系统、双人格

共享部分：

- PageShell 透明页壳，透出 AmbientBackground。
- PageActHeader 作为工具页统一页头，提供「中文 · ENGLISH」kicker、标题和短描述。
- GlassCard 作为唯一玻璃表面，不手写第三套玻璃卡。
- primary 作为主操作色；状态使用 success/warning/error/info 语义 token。
- default/hover/focus-visible/active/disabled/loading/error 状态完整。
- 一屏最多一个 primary CTA。

人格差异：

- 塔罗：静谧仪式、中央牌桌、线性阶段、阅读友好；tech-purple 仅作少量神秘语义点缀。
- 生图：精密创作台、高优先输入、参数清晰、结果图片承担主要色彩；页面本身保持中性。

### 2.2 每页一个视觉“哇点”

- 塔罗：牌桌从抽牌到翻牌、形成牌阵的叙事动效。
- 生图：结果画布从骨架到真实比例图片的平滑呈现。

其他区域保持安静，不叠加持续光扫、漂浮、粒子或脉冲。

### 2.3 稳定性先于视觉

实施顺序固定为：

1. 流程竞态、键盘与数据健壮性。
2. 状态反馈、灯箱和结果闭环。
3. 布局与响应式。
4. 材质、排版和微动效。

## 3. 信息架构与共享结构

### 3.1 工具页公共骨架

```text
PageShell
├── 轻量返回路径：百宝箱 / 当前工具
├── PageActHeader
├── 主工作区
├── 上下文区（进度、历史或帮助）
└── 页内说明/免责声明
```

返回路径不新增第三种大页头，只提供紧凑、键盘可达的返回入口。Navbar 的桌面工具下拉需同步支持键盘打开与焦点管理。

### 3.2 统一状态语言

| 状态 | 视觉与语义 |
|---|---|
| Idle | 提供下一步主操作，辅助操作降级为 outline/ghost |
| Loading | 稳定尺寸骨架或进度说明；`aria-busy=true`；允许取消时明确显示取消按钮 |
| Error | 错误图标 + 原因 + 主动作（重试）+ 必要的次动作；`role=alert` |
| Empty | 复用 EmptyState：图形 + 一句话 + 可执行动作 |
| Success | 结果优先，成功提示轻量，不使用持续闪烁 |
| Disabled | 解释不可操作原因，不仅降低透明度 |

## 4. 塔罗页设计

### 4.1 桌面布局

1280px 以上采用三栏，但中央牌桌不得低于可用宽度的 58%：

```text
左侧进程轨（约 170px） | 中央牌桌（主区域） | 右侧上下文（约 190px）
```

左侧：

- 四步进程：问牌、洗切、抽牌、解读。
- 当前步骤清晰标记，已完成步骤仅显示完成状态，不允许任意跳回破坏状态。
- 今日一牌提供紧凑缩略入口。

中央：

- 问题输入与单张/三张牌阵选择。
- 洗牌、切牌、抽牌、翻牌共享稳定的牌桌尺寸，阶段切换不引起大幅 CLS。
- 主 CTA 位于当前任务之后，文案随阶段变化。

右侧：

- 统计摘要。
- 最近一次历史。
- 快捷键帮助。
- 空间不足时整栏移至结果下方，不压缩中央牌桌。

全部翻开后，结果区顺序固定：

1. 单牌牌义。
2. 三张牌整体联动（适用时）。
3. AI 深度解读。
4. 分享、复制、重新占卜。

### 4.2 移动与平板

| 宽度 | 结构 |
|---|---|
| 320–474px | 单列；顶部紧凑四步进度；牌堆采用横向可操作方案或“代我抽牌”，避免 78 个重叠按钮和 78 次 Tab |
| 475–833px | 中央牌桌为主；历史/统计折叠到结果下方 |
| 834–1279px | 中央牌桌 + 单侧上下文栏 |
| 1280px+ | 三栏，中央最少 58% |

所有 Tab、收藏、翻牌、撤销和灯箱控制的触摸目标至少 44×44px。

### 4.3 单向状态机

```text
ASK → SHUFFLE → CUT → DRAW → REVEAL → READING
```

约束：

- 每个阶段只暴露当前有效操作。
- reset/Esc 后旧异步任务不得再改变阶段。
- 单张抽满 1 张、三张抽满 3 张才可进入 reveal。
- 全部翻开后历史和统计只保存一次。
- 牌义速查按需挂载或延迟初始化，避免隐藏面板承担首屏成本。

### 4.4 必修问题（P1）

1. 跳过洗牌时先清除原 900ms timer，防止进入 DRAW 后被旧 timer 改回 CUT。
2. TarotCutDeck 保存 timeout id 并在卸载/reset 时 cleanup，防止 stale `onCut`。
3. 快捷键 hook 排除 `button`、`a`、tab、role=button 等原生交互目标；Space 只在页面非交互区域触发快捷操作。
4. ShareCard 等弹层打开时，Esc 只关闭最上层弹层并恢复触发按钮焦点，不同时 reset 占卜。
5. 未翻开的牌面从可访问树隐藏；翻开后播报牌位、牌名、正/逆位。
6. localStorage 读取、解析和写入全部 try/catch；不可用时降级为本次会话，不阻断占卜。
7. 牌义 Tab 补齐 `aria-controls`、`tabpanel`、`aria-labelledby`、左右箭头和 roving tabindex。
8. 每日牌在 effect 完成前提供稳定占位；“以此占卜”清理旧问题并正确 dismiss 首次引导。

### 4.5 动效规范

- 洗牌、切牌、翻牌只动画 transform/opacity。
- UI 反馈不超过 300ms；阶段转场不超过 500ms。
- 牌桌尺寸不随 hover、标签或加载文案变化。
- reduced-motion 下：
  - 洗牌/切牌直接进入稳定终态。
  - 翻牌无 3D 旋转，改为即时内容切换或淡入。
  - 不启用持续呼吸/漂浮。
  - 所有流程功能保持可用。

### 4.6 历史与破坏操作

- 历史清空需确认或提供短时撤销反馈。
- 首屏只显示最近一次与摘要，完整历史折叠展开。
- storage 损坏时忽略坏数据并显示非阻断提示，不让页面崩溃。

## 5. 图片生成页设计

### 5.1 访问策略

- 页面和生成接口均允许游客使用，符合“只有后台管理需要登录”。
- 后端按 IP 进行生成限流；前端展示剩余额度/冷却信息（若后端可返回）。
- 401/403 不作为默认流程；若服务配置要求认证或额度不足，显示准确原因和下一步动作。
- 提示词最大 1000 字，张数保持 1/2/4，服务端再次校验。

### 5.2 桌面布局

834px 以上使用 35/65 左右双栏：

左侧固定创作参数栏：

1. 提示词 textarea + 字符计数。
2. 示例提示词 chips。
3. 画幅/尺寸分段控件，并以比例小图而非仅尺寸文字表达。
4. 张数 1/2/4 分段控件。
5. 主 CTA“生成图片”。
6. 生成中替换为进度说明 + 明确取消操作。

右侧结果画布：

- 空闲时展示 EmptyState，而非空白区域。
- 生成时使用与目标比例一致的骨架，避免结果出现时跳位。
- 1/2/4 张按真实比例展示；不再统一 `aspect-square object-cover` 裁切。
- 每张图有查看、下载、分享等工具操作；图标按钮配 tooltip。
- 顶部提供“下载全部”和“新一轮”，但不与单图主操作争抢层级。
- 底部展示本次会话最近 5 次历史。

### 5.3 移动布局

- 320–474px：单列；提示词、参数、主操作、单列真实比例结果、折叠会话历史。
- 475–833px：单列编辑区 + 两列结果；会话历史横向滚动。
- 主 CTA 不固定在视口底部，避免遮挡内容和键盘。
- 尺寸与张数控件可横向排列，但每个目标至少 44px。

### 5.4 可恢复状态机

```text
IDLE → VALIDATING → GENERATING → DONE
                   ↘ ERROR / EMPTY / CANCELLED / QUOTA
```

规则：

- 本地校验失败不发请求，焦点移至有问题字段，并显示关联错误。
- GENERATING 使用 AbortController；取消、离开页面或新请求开始时中止旧请求。
- 失败、取消、空结果都保留提示词与参数。
- 第二次生成不得串入第一次请求结果。
- 成功结果加入页面内会话历史；刷新后清空。

### 5.5 API 与结果健壮性（P1）

1. API 客户端保留 HTTP status 和结构化错误码，不靠英文错误字符串判断 401/403。
2. 响应必须校验 `images` 为非空、元素为合法 URL 的数组；malformed 响应进入 error。
3. `images=[]` 进入 EmptyState，提供“调整提示词”和“重新生成”。
4. localStorage/token 读取异常不能让点击生成直接抛错；公开生成不应依赖 token。
5. 单图使用加载占位和 `onError` fallback；失效图不显示破图图标。
6. loading 使用 `aria-busy` 和可感知状态；错误使用 `role=alert`；完成使用适度 `aria-live`。
7. reduced-motion 下不使用旋转 loading keyframe，改为静态图标 + 文案/进度。

### 5.6 本次会话历史

历史仅存在于页面内存，最多 5 组，每组包含：

```text
id, createdAt, prompt, size, count, imageUrls
```

行为：

- 新结果插入最前，超出 5 组移除最旧项。
- 点击历史组恢复其参数和结果到主画布，不自动重新请求。
- 明确标注“仅本次会话保留，刷新后清空”。
- URL 失效时显示单图错误，不阻断同组其他图片。
- 不使用 IndexedDB，不持久化图片二进制。

### 5.7 Lightbox 完整闭环

共享 Lightbox 的改动应保持其他调用方兼容：

- 根节点 `role=dialog`、`aria-modal=true`、标题关联。
- 打开时焦点进入；Tab/Shift+Tab 不逃逸；关闭后恢复到原缩略图按钮。
- Esc 关闭，左右方向键切图；键盘动作不与页面快捷键冲突。
- 控制栏视觉可自动淡化，但不可从 DOM 移除；聚焦、鼠标移动或触摸时恢复。
- fullscreenchange 作为真实状态来源；进入和退出都调用浏览器 Fullscreen API。
- 下载提供 downloading/success/error 状态；失败可重试。
- 根据响应 Content-Type 或 URL 安全推断扩展名，不强制 `.jpg`。
- 外部临时图片继续允许原生 `<img>`，代码旁保留中文原因说明。
- reduced-motion 下关闭缩放/切图转场。

## 6. 导航、主题与视觉细节

### 6.1 导航

桌面 Navbar 工具下拉：

- hover、focus、Enter、Space、ArrowDown 均可打开。
- Esc 关闭并还原焦点。
- 关闭状态的子链接使用 inert/aria-hidden 或 tabIndex 管理，不能聚焦到不可见菜单。
- 移动菜单保持塔罗与图片生成入口。

### 6.2 色彩比例

塔罗：

- 中性背景/玻璃约 80%。
- primary 约 12%。
- tech-purple 不超过 8%，仅用于牌阵、AI 或神秘语义点缀。

生图：

- 中性背景/玻璃约 85%。
- primary 约 10%。
- 状态色约 5%。
- 结果图片承担主要色彩，UI 不与图片争夺注意力。

所有组件只消费语义 token，不新增裸 hex 或 `isDark ? A : B` 分支。

### 6.3 排版与密度

- PageActHeader 标题保持工具页尺度，不使用营销 hero 大字。
- 正文和说明最大行长约 68 字符。
- 参数标签、计数和状态使用 footnote/caption 阶梯。
- AI 解读长文本使用舒适行高并限制正文宽度。
- 数字计数使用 tabular-nums 防布局跳动。

## 7. 可访问性验收

按 WCAG 2.2 AA：

1. 所有交互目标至少 44×44px。
2. 正文对比度至少 4.5:1。
3. 焦点始终可见，页面与弹层无焦点丢失。
4. 模态具备 focus trap、Esc 和 focus restore。
5. Tab 具备完整语义和键盘导航。
6. 未翻牌不泄露结果；翻牌后提供准确播报。
7. loading/error/empty/success 对读屏可感知。
8. light/dark/reduced-motion 均可完成全部主流程。
9. axe 测试 0 critical/serious。

## 8. 性能预算

| 指标 | 预算 | 措施 |
|---|---|---|
| LCP | ≤ 2.0s | 延迟非当前速查视图、历史与重组件；图片骨架稳定 |
| INP | ≤ 200ms | 只动画 transform/opacity；避免 78 个移动端重叠交互节点 |
| CLS | ≤ 0.05 | 牌桌和图片结果预设尺寸/比例；每日牌使用占位 |
| 动效 | 60fps | 不新增循环装饰；will-change 仅短时使用 |
| 请求 | 可取消 | AbortController；卸载和二次生成清理旧请求 |
| DOM | 控制规模 | 非当前面板按需挂载；移动牌堆提供简化交互 |

## 9. 测试矩阵

### 9.1 塔罗自动化

- 跳过洗牌后推进超过 900ms，仍处于正确阶段。
- 切牌中 Esc/reset 后等待 1s，不被 stale callback 改回 DRAW。
- focus 在 button/link/tab 时 Space 只触发原控件；页面空白才触发快捷操作。
- 单张/三张抽满条件、撤销、重复选牌和逐张/全部翻牌。
- ShareCard 打开后 Esc 只关弹层并恢复焦点。
- localStorage 禁用、坏 JSON、超限时仍可完成占卜。
- 全部翻开只保存一次历史/统计。
- 未翻牌和已翻牌读屏语义。
- ask/draw/reveal/reading/share 全阶段 axe 测试。

### 9.2 生图自动化

- 输入字段、字符计数、尺寸/张数 group 语义。
- 正常返回 1/2/4 张。
- `[]`、malformed、401、403、429、网络异常。
- loading 禁用、aria-busy、取消、二次生成不串结果。
- 会话历史新增、最多 5 组、恢复参数与结果。
- 单图加载失败和临时 URL 失效。
- Lightbox 打开/关闭、焦点循环、方向键、全屏进入/退出。
- 下载成功/失败和扩展名。
- image-gen 页面与 Lightbox axe 测试。

### 9.3 浏览器走查

视口：320、375、393、768、1024、1440px。  
组合：light、dark、reduced-motion。  
输入：鼠标、键盘、触摸。  
检查：无横向裁切、无重叠、真实比例、Navbar 键盘入口、焦点顺序、状态反馈。

### 阶段 1：稳定性与语义

## 11. 完成定义

只有同时满足以下条件才算完成：

- 两页主流程在未登录状态可完整使用。
- 塔罗不存在 timer 回退、stale callback、快捷键抢占或弹层 Esc 重置。
