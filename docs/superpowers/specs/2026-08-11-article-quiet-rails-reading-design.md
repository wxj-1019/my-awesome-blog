# 文章详情页「安静三轨」沉浸阅读设计

日期：2026-08-11  
范围：`/articles/[id]` 文章详情页（文章列表页仅做必要衔接，不作为本期主改造对象）

## 1. 目标

在保留站点「深海 × 电影 + 玻璃拟态」语言的前提下，把文章详情页从“多张玻璃卡片堆叠”调整为“正文主导、两侧安静辅助”的长文阅读界面。

核心目标：

- 正文始终是唯一视觉主角，侧栏提供导航和内容发现，但不与正文竞争。
- 控制中文阅读行宽、字号、行高、段间距与章节节奏，提高长文舒适度。
- 统一封面、标题、正文的中心线，消除宽封面与窄正文之间的视觉跳变。
- 收敛文章末尾标签、数据、作者、评论的卡片数量，形成连续阅读结束区。
- 修正当前 sticky 定位冲突，确保桌面双侧栏稳定跟随滚动。
- 清理 Markdown 深色硬编码，保证浅色和深色主题下都自然可读。

## 2. 选定方向

采用 **A · 安静三轨**：

- 左轨：阅读进度 + 文章目录 + 返回列表。
- 中轨：封面后的标题信息、正文、文章结束区、评论。
- 右轨：轻量相关文章。
- 两侧仅在 `xl` 及以上进入完整三轨并 sticky；平板及以下让正文优先，目录改用抽屉，相关文章落到正文后。

不采用：

- “杂志舞台”：视觉强，但封面和推荐内容会持续干扰长文阅读。
- “纯净阅读器”：干扰最少，但目录和相关文章默认隐藏，降低可发现性。

## 3. 当前问题

### 3.1 布局与 sticky

- 外层已放宽到 `1400px`，但正文仍为 `max-w-3xl`；行宽本身接近合理值，不应继续无限放宽。
- 左轨 class 同时包含 `xl:top-24` 和 `xl:top-auto`，后者覆盖前者，sticky 顶距不稳定。
- `ArticleTocRail` 自身和父级 aside 都承担 sticky，职责重复。
- 右轨父级与 `GlassCard` 内部 sticky 重复，后续扩展容易出现滚动边界异常。
- `lg–xl` 左轨使用 viewport fixed，可能遮挡内容；此区间更适合正文优先 + 目录抽屉。

### 3.2 阅读排版

- 正文使用宋体与 `1.8` 行高，方向正确，但字号、行宽和段落节奏没有形成统一阅读令牌。
- `.prose` 首段首字下沉全局启用，短段落、移动端或图片开头可能出现不协调。
- MarkdownRenderer 中大量 `text-white/*`、`slate-*`、`border-white/*`，浅色主题下对比和材质不稳定。
- 引用块整段斜体不适合中文长引用。
- 代码、表格、图片的垂直节奏偏紧，连续阅读时内容块之间缺少呼吸。

### 3.3 信息层级

- 封面横跨大容器，标题元信息却未与正文中心线统一。
- 正文后连续出现标签、四张统计卡、作者卡、评论卡，边界过多，阅读结束阶段碎片化。
- 相关文章每条都有 HoverLift，右侧栏动效和立体感偏强。
- 移动端目录按钮固定在右下角，可能与评论输入、浏览器底栏或其它悬浮控件争用空间。

## 4. 布局设计

### 4.1 桌面 `xl+` 三轨

外层容器：

- `max-w-[1440px] mx-auto px-4 md:px-6`
- 使用 CSS Grid，不再使用 `flex` 模拟三栏。

轨道建议：

```text
xl:   208px | minmax(0, 1fr) | 224px
2xl:  224px | minmax(0, 800px) | 256px
间距: xl 24px / 2xl 32px
```

Tailwind 形态：

```text
xl:grid-cols-[13rem_minmax(0,1fr)_14rem]
2xl:grid-cols-[14rem_minmax(0,50rem)_16rem]
```

正文实际排版仍限制为约 `72ch`，多余宽度用于舒适留白，不拉长单行。

### 4.2 sticky 所有权

- sticky 只由左右 `aside` 父级负责。
- 左右统一 `xl:sticky xl:top-24 xl:self-start`。
- 左目录最大高度 `calc(100dvh - 7rem)`，内部目录列表独立滚动。
- 右相关文章最多 4–5 条，避免侧栏高度超过视口。
- 移除 `ArticleTocRail` 和右侧 `GlassCard` 内部的重复 sticky。

### 4.3 平板与移动端

- `< xl` 不显示桌面左右轨。
- 目录入口使用抽屉，断点从当前 `lg:hidden` 调整为 `xl:hidden`。
- 相关文章放到评论前或文章结束区后，以轻量横向/单列列表呈现。
- 目录浮动按钮避开右下角评论和其它浮层：优先放在阅读进度条下方的固定边缘入口，或使用 `bottom-[calc(env(safe-area-inset-bottom)+1.5rem)]`。
- 触控目标保持至少 44×44px。

## 5. 封面与标题舞台

- 封面保持克制高度：移动端约 `200–240px`，桌面约 `280–320px`，不占满首屏。
- 封面可横跨外层容器，但标题、分类、阅读时间、作者、日期、阅读量和互动操作统一收进与正文一致的中心列。
- 标题最大宽度与正文一致，中文标题使用思源宋体；字号保持页面级，不继续放大。
- 元信息分两层：
  - 第一层：分类、阅读时长。
  - 第二层：作者、日期、阅读量 + 点赞/收藏/分享。
- 移动端互动按钮允许换行，但不使用固定宽度；图标按钮保留可见文字或 aria-label。
- 封面 Ken Burns 保留为唯一氛围动效之一，继续尊重 reduced-motion，不新增持续动画。

## 6. 正文阅读设计

### 6.1 阅读令牌

正文阅读面：

- 行宽：`max-width: 72ch`。
- 移动端字号：`16px`。
- 桌面字号：约 `17–18px`。
- 行高：约 `1.8–1.85`。
- 中文字间距：`0.01–0.015em`，不使用负字距。
- 段间距：约 `0.95em`。

正文卡片：

- 使用较低层级玻璃表面或近似纸面背景。
- 降低 blur、阴影和边框强度，不使用工具卡式重悬浮感。
- 内边距：移动 `p-5`，桌面 `p-8` 或 `p-10`。

### 6.2 标题节奏

- `h2`：章节级，顶部间距约 `2.2em`，下方约 `0.7em`，可加短引导线或轻量底边。
- `h3`：子章节级，顶部约 `1.7em`，字号与权重低于 h2。
- `h4–h6`：继续收敛，不让所有标题同样醒目。
- 锚点 `scroll-mt-24` 保留，与固定导航和目录跳转匹配。

### 6.3 首字下沉

- 仅文章正文第一段启用。
- 仅在 `md+` 开启；移动端关闭。
- 若首段为图片、列表、代码或段落过短，不强行下沉。
- 通过文章正文专用 class 限定，不再影响所有 `.prose` 场景（例如 AI 输出、评论或其它 Markdown）。

### 6.4 Markdown 内容块

颜色：

- 清理 `text-white/*`、`bg-slate-*`、`border-white/*`。
- 改用 `text-foreground`、`text-muted-foreground`、`bg-muted`、`bg-card`、`border-border`、`text-primary`。

引用：

- 细主色竖线 + 低对比底色。
- 中文正文保持正常字形，不整段 italic；仅 `<em>` 斜体。

代码：

- 语言标识 + 复制按钮保留。
- 背景改为主题语义色，降低与正文的亮度反差。
- 移动端保持可横向滚动，不压缩代码字号。
- 复制按钮补 `type="button"`、aria-label 和复制成功状态（若现有 hook 可复用则复用）。

表格：

- 窄屏横向滚动。
- 表头使用 `bg-muted/60`、正文使用语义文字色。
- 行分隔改为 `border-border`，避免深色专用白边。

图片：

- 统一圆角、上下间距和边框语义色。
- 限制极长图片的视觉占用；保持 `object-contain` 与原始比例。
- 图片 alt 与加载失败回退保留。

## 7. 文章结束区

正文结束后改为连续的“阅读收束区”，减少玻璃卡数量。

顺序：

1. 标签：紧贴正文末尾，作为内容语义延伸。
2. 数据带：把点赞、评论、分享、阅读量从四张卡合并为一条安静的横向信息带；移动端可 2×2。
3. 作者信息：单个低层级信息面，头像、简介、声誉、关注者、关注操作集中呈现。
4. 相关文章：桌面在右轨；`< xl` 在作者信息后呈现轻量列表。
5. 评论：作为独立互动区，视觉层级低于正文标题，但输入区域清晰。

作者和评论继续使用清晰边界，但避免每一块都使用同样强度的阴影和玻璃效果。

## 8. 侧栏视觉

### 8.1 左目录

- 顶部显示“目录 + 阅读百分比”。
- 进度条变细，作为辅助反馈。
- 当前章节使用左侧短线/文字主色，不使用大面积 `bg-primary/20`。
- 非当前章节降低对比，但仍满足可读性。
- 目录内部滚动条保持轻量。
- “返回列表”使用低强调 ghost 操作。

### 8.2 右相关文章

- 标题与阅读量保留，分类作为小型文字标签。
- 移除每条 HoverLift；仅使用边框/背景/文字色的微交互。
- 最多显示 4–5 条。
- 可在底部增加“查看全部文章”低强调链接。

## 9. 动效与可访问性

- 不新增持续循环动画。
- 保留封面 Ken Burns 与一次性正文 reveal；reduced-motion 下均静态。
- sticky 不遮挡固定导航、阅读进度条或目录锚点。
- 目录按钮保持 `aria-current` 或等价当前章节语义。
- 所有图标按钮提供 aria-label；评论输入保持 label。
- 标题层级从页面 h1 → 正文 h2/h3 连续；Markdown 内容中的额外 h1 需要映射/降级策略，避免多个页面主标题。
- 明暗主题正文、代码、引用、表格对比度满足 WCAG AA。

## 10. 数据与错误处理

- 本期不修改文章 API、评论 API 或数据结构。
- 终端 `curl` 输出出现的中文乱码不直接判定为后端数据错误；实施阶段用浏览器渲染、响应头 charset 和原始字节单独验证。
- 若确认 API 本身存储或返回乱码，另立修复任务，不把编码修复夹带在 UI 改造中。
- 相关文章或评论加载失败时，正文继续可读；辅助区展示轻量错误状态，不阻断文章。

- 文章列表页主要信息架构。
- 全站主题 token 与导航。
- 与文章阅读无关的页面。

## 12. 验收标准

- `xl+` 为稳定三轨，左右侧栏随滚动并无 sticky/top 冲突。
- 正文行宽约 72ch，大屏不出现过长文本行。
- 平板/移动端不出现固定侧栏遮挡；目录抽屉可用且不遮评论输入。
- 封面、标题、正文中心线关系稳定，页面滚动时视觉重心不跳。
- 标签/数据/作者/评论结束区比现状减少卡片碎片感。
- Markdown 代码、引用、表格、图片在 light/dark 下可读。
- reduced-motion 下无新增动效。
- 相关单测、a11y、lint、type-check、build 通过。
- 至少浏览器检查 390×844、1280×900、1536×960 三个视口，验证无横向溢出、重叠或 sticky 失效。
