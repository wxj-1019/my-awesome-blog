## 产品概述

修复后台管理系统访问问题，确保用户点击后台管理系统链接时能够正确跳转到后台管理页面，而不是首页。

## 核心功能

- 移除 Next.js 配置中错误的重定向规则（/admin 重定向到 /）
- 在后台管理系统的布局中添加认证保护，确保只有已登录用户才能访问
- 调整中间件配置，避免与客户端认证保护冲突
- 确保认证流程正常工作，未登录用户被重定向到登录页面

## 技术栈

基于现有项目技术栈：

- 前端框架：Next.js (React + TypeScript)
- 样式：Tailwind CSS
- 组件库：shadcn/ui
- 认证方式：JWT 令牌存储在 localStorage

## 实现方案

### 问题分析

1. **重定向问题**：`frontend/next.config.mjs` 中配置了 `/admin` 到 `/` 的永久重定向，导致用户无法访问后台管理页面
2. **认证保护缺失**：后台管理布局 (`frontend/src/app/admin/layout.tsx`) 未包装 `ProtectedRoute` 组件
3. **中间件冲突**：中间件 (`frontend/src/middleware.ts`) 配置了 `/admin` 路径保护，但由于令牌存储在 localStorage 中，中间件无法正确识别已认证用户，可能导致重定向循环

### 解决方案

1. **移除错误重定向**：删除 `next.config.mjs` 中 `/admin` 到 `/` 的重定向规则
2. **添加客户端认证保护**：在 admin 布局中包装 `ProtectedRoute` 组件，确保只有认证用户才能访问
3. **调整中间件配置**：从中间件的受保护路径中移除 `/admin`，完全依赖客户端认证保护
4. **保持现有认证流程**：继续使用现有的 `ProtectedRoute` 组件和认证 API

### 实现细节

- **文件修改**：
- `frontend/next.config.mjs`：移除 `/admin` 重定向规则
- `frontend/src/app/admin/layout.tsx`：导入并使用 `ProtectedRoute` 组件包装子内容
- `frontend/src/middleware.ts`：从 `protectedPaths` 数组中移除 `/admin`
- **兼容性考虑**：保持现有认证流程不变，避免影响其他功能
- **错误处理**：确保未登录用户被正确重定向到登录页面，并保留原始路径以便登录后跳转

### 性能与安全

- **性能**：客户端认证检查在组件挂载时进行，对页面加载性能影响极小
- **安全**：客户端认证保护与中间件保护相结合，确保只有认证用户能访问敏感路径
- **用户体验**：未登录用户看到清晰的认证提示和重定向，登录后能返回原页面
